# Codex 与 ChatGPT Work 共享用量池：合并之后额度怎么规划（2026）

> 口径:官方文档明确 Work/Codex 同池计量;2026 年 7 月起成为用户必须知道的事实。

白天用 ChatGPT Work 跑文档,晚上用 Codex 写代码,月底发现额度总是提前见底——2026 年 7 月之后,这不是错觉:**两边烧的是同一桶油**。

先说结论：

1. **同一个计量池**:Work 的智能体任务和 Codex 的编程任务,消耗同一份额度。
2. 限额结构不变:5 小时窗口 + 周上限,双层同时管这个池子。
3. 规划核心:**按周做预算,而不是按任务类型**——池子只有一口,分类记账没意义。

## 共池的机制

官方文档写明:ChatGPT Work 和 Codex 走同一个 agentic 用量池。你发起的任何智能体任务——不管是改代码、处理表格还是汇总文档——都从同一处扣减。

这个设计的逻辑:Codex 和 Work 底层是同一套智能体执行设施(沙盒、工具调用、计量),任务形态不同、引擎相同。**计量跟着引擎走,不跟着界面走**。

7 月的[限额风波](codex-5h-limit-saga-2026.md)让这个机制广为人知:5 小时窗口临时取消的十八天里,长任务更容易在不知不觉中把周额度吃空——因为「编程的额度」和「办公的额度」不再分家。

## 个人怎么规划

**按周记账。** 用量页看的是周趋势,不是单日:你的真实用量 = 编程 + 文档 + 自动化任务的总和。觉得自己「没怎么用 Codex 却撞限」的,八成是 Work 侧的消耗被忽略了。

**任务分级。** 同一个池子,更要省着烧:

- 简单问答走普通对话(不占 agentic 池)
- 中等任务选轻量模型(额度拉长 2.5-3.3 倍,见[额度算账](../08-chatgpt-deep-dive/codex-quota-supplement-guide-2026.md))
- 重任务才上旗舰档 + 并行

**自动化任务单列预算。** 定时任务、Routines 类的持续消耗,按「频率 × 单次消耗」折算成周占用——自动化是共池时代最容易失控的口子。

## 团队怎么规划

- **用量透明化**:共享池 + 多人使用 = 谁都以为自己是轻度用户。定期拉全员用量,把「额度去哪了」变成可讨论的事实
- **错峰安排**:批量任务挪到低峰时段,窗口利用率更高
- **先例可参考**:2026 年 7 月重置 bug 期间,官方给约 50 万受影响用户补发了额度——**保留自己的用量记录,遇到官方事故时有据可查**

## FAQ

Q: 普通对话也占这个池吗?

A: 不占。标准 ChatGPT 对话有独立的额度体系;共池的是 agentic 任务(Codex、Work 的智能体执行)。

Q: 深度研究算吗?

A: 深度研究有独立的次数计量(如 Plus 10 次/月),与 agentic 池分开——三本账别混。

Q: 撞限了优先怎么办?

A: 先 `/status` 分清是窗口还是周上限(处理见[用量说明](../03-codex-tutorials/codex-usage-limits-2026.md)),再按[三条路算账](../08-chatgpt-deep-dive/codex-quota-supplement-guide-2026.md)决定等、买还是升。
