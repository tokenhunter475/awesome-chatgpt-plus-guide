# Codex 定时任务实战：让 AI 值班的三种玩法与额度纪律（2026）

> 功能口径:Codex 桌面版 Automations;自动化必有消耗,纪律先行。

有一类活最磨人:不难,但每天都得做。commit 巡检、站会日报、CI 失败汇总、依赖检查——Codex 桌面版的定时任务(Automations)就是冲着这类活来的:配置一次,每天自动跑。这篇给三种可直接抄的玩法,和三条必须守的纪律。

先说结论：

1. 定时任务 = **在指定时间自动执行的 Agent 任务**,桌面版独有(CLI/IDE 插件没有)。
2. 最先值得自动化的三类:**每日巡检、周期汇报、持续盯防**。
3. 三个前提:**额度预算、权限收敛、人工抽检**——缺一条,自动化会从省心变成惊吓。

## 玩法一:每日巡检(最实用的起点)

官方模板「扫描最近提交」直接可用:每天早上自动检查过去 24h 的 commit,标出潜在 bug 和修复建议。

自定义升级版:把巡检范围写具体——「检查 src/api/ 下的改动,重点关注错误处理和权限校验,输出按严重度排序的清单」。**任务描述越具体,巡检的信噪比越高**;描述模糊的定时任务,产出一堆正确的废话。

## 玩法二:周期汇报(站会救星)

「Git 日报」模板:总结昨天的 git 活动,生成站会汇报素材。「生成周报」模板:从已合并 PR 提炼 release notes。

用法要点:汇报类任务的产出要**稳定格式**——在任务描述里固定输出结构(改了什么/为什么/风险点),每天的日报才有可比性。格式漂移的日报,三天后你自己就不看了。

## 玩法三:持续盯防

「CI 失败汇总」:盯着 CI 的失败和不稳定测试,给修复建议。「依赖漂移检测」:监控依赖和 SDK 版本变化。这类任务的价值在**连续性**——单次看没什么,连续跑两周,漂移和劣化趋势就显形了。

## 三条纪律(缺一不可)

**纪律一:额度预算。** 定时任务和手动任务共用同一个用量池(见[额度机制](../03-codex-tutorials/codex-usage-limits-2026.md))。每天一次的巡检无所谓;每小时一次的监控,月底对账时会看到惊喜——反面案例见[血的教训](../06-api-and-relays/ai-pitfalls-lessons-2026.md)的深夜脚本故事。**频率 × 单次消耗 = 月账单,配置前先算。**

**纪律二:权限收敛。** 定时任务在没人盯着的时候跑——写权限收到最小(只读 + 产出报告最稳),要改代码的任务产出 PR 由人合并,别让它直接 push。

**纪律三:人工抽检。** 每周抽一次自动产出的正确样本人工复核。自动化的意义是「把重复劳动变成抽查」,不是「设置完就永不用管」——这是[工作流实战](../03-codex-tutorials/codex-workflow-guide-2026.md)里「人工验收不可替代」在值班场景的翻版。

## FAQ

Q: 定时任务在哪配?

A: Codex 桌面版的 Automations,官方模板一键启用,自定义任务按提示词写法描述即可(模板库见[桌面版评测](codex-desktop-app-review-2026.md))。

Q: 电脑关了任务还跑吗?

A: 桌面版 Automations 依赖本地应用;要「关机也跑」的云端值班形态,看 Claude Code 的 Routines(Anthropic 托管运行,见[对比](../07-industry-watch/claude-code-routines-2026.md))——两边路线不同。

Q: 任务失败了会通知吗?

A: 以产品内通知机制为准。稳妥做法:把「失败时输出简短失败报告」写进任务描述,至少日志里能追。

Q: 免费用户能用定时任务吗?

A: 桌面版曾对 Free/Go 限时开放,窗口随时调整,以产品内实际权限为准。
