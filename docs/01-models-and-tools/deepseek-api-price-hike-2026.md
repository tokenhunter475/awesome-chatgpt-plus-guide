# DeepSeek API 涨价解读：峰谷定价、缓存命中涨 1100%，开发者怎么算账（2026）

> 事实口径：8 月 13 日官宣，2026 年 8 月 17 日 0 点（北京时间）生效。

DeepSeek 这次调价不是小调整：全线改为峰谷分时计价，多项价格翻倍到十倍。受冲击最大的是「白天高频调用 + 长上下文」的开发者——恰好是编程 Agent 用户的典型画像。这篇把价格变化和应对路径讲清。

懒得看全文？重点就这几条：

1. **调用量小、能错峰的**：影响有限，空闲时段价格是高峰一半，把任务挪时段就行。
2. **白天高频写代码、跑 Agent 的**：成本最高涨到原来的 3 倍多，需要重新算账（下文有示例）。
3. **依赖缓存命中的长上下文场景**（编程助手、RAG）受伤最重——涨幅最大的正是缓存命中输入价。

|---|---|---|---|---|

|---|---|---|---|---|

高峰时段：每天 9:00–12:00、14:00–18:00（北京时间），正好覆盖工作时间；空闲价格为高峰一半。

背景值得记住：2026 年 5 月，DeepSeek 刚把 2.5 折优惠价转为「永久定价」，不到三个月「永久」结束。

## 为什么编程场景被打得最疼

涨幅最大的不是输出，是**缓存命中输入**（+1100%）。编程助手和 Agent 的工作方式决定了 token 结构：每一轮都要把对话历史、代码库上下文重新发给模型，输入通常是输出的几十倍，其中大部分走缓存命中。

峰谷规则再加一刀：写代码集中在白天，9-18 点几乎全落进高峰时段，不像跑批任务能挪到半夜。两件事叠加，开发者基本只能按最高价交钱。

## 算一笔账（假设已标注，量级供参考）

一个重度 Agent 用户的典型量级：每天输入 5000 万 tokens（80% 缓存命中）+ 输出 200 万 tokens。按 V4-Pro 计：

- 涨价前：约 43 元/天，每月 22 个工作日约 **950 元**
- 涨价后（工作时段高峰价）：约 156 元/天，每月约 **3,400 元**
- 涨价后（全部挪到空闲时段）：约 78 元/天，每月约 **1,700 元**

实际数字随工具和用法浮动，但结构结论稳定：**高峰重度用户成本约 3.5 倍，错峰可对冲一半**。

对照固定月费的订阅：ChatGPT Plus 官方 $20/月（含 Codex 使用），重度场景下按量计费的浮动线已明显压过订阅的固定线。订阅的额度规则（5 小时窗口 + 周上限）见 [Codex 用量上限说明](../03-codex-tutorials/codex-usage-limits-2026.md)。

## 三条路怎么选

**继续用 DeepSeek**：调用量小、能错峰、夜间跑批的，空闲时段价格仍是低位，没必要折腾。

**错峰 + 调度优化**：批量任务挪到空闲时段，重写缓存策略降低重复上下文，适合任务时间自由的场景。

**换订阅模式**：白天高频编程的用户，固定月费的订阅（含编程 Agent）成本可预测，不受峰谷表和下次「整体上调」影响。Codex 的能力与 GPT-5.6 档位见[编程工具对比](ai-coding-tools-comparison-2026.md)。

平心而论，7×24 不间断的自动化流水线替代不了按量付费——订阅有周上限，超量要等重置。这类场景的正解是继续按量 + 错峰。

## FAQ

Q: 涨价影响网页版/App 的免费使用吗？

A: 不影响。这次调整的是 API 按量计费价格，网页版和 App 仍免费。

Q: 高峰时段具体是几点？

A: 每天 9:00–12:00 和 14:00–18:00（北京时间），其余为空闲时段，价格为高峰一半。

Q: 为什么缓存命中涨得最多？

A: 它原本定价极低（0.025 元/百万 token），是长上下文场景的成本支柱。编程 Agent 和 RAG 高度依赖它，涨价直接改变这类场景的成本结构。

Q: 自部署开源版受影响吗？

A: 不受 API 定价影响——自己部署只花硬件和运维成本，这正是开源的避险价值（见[开源 vs 闭源](open-source-vs-closed-source-models-2026.md)）。
