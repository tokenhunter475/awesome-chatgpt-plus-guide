# AI Agent 是什么？和普通 AI 对话有什么区别（2026）

> 本文是 AI 基础概念第 3 篇；Agent 产品迭代很快，具体功能以各产品官方文档为准。

2026 年科技圈说得最多的词从「大模型」换成了「Agent」。OpenAI、Anthropic、Google 都在把产品往 Agent 方向做。这篇讲清 Agent 到底是什么、和你平时用的对话 AI 差在哪。

挑重点说：

1. **模型是大脑，Agent 是装上手脚的大脑**——普通对话 AI 只能「说」，Agent 能「做」：拆任务、调工具、执行操作、检查结果。
2. 判断标准就一条：**任务是你在推进，还是 AI 自己在推进**。你一句句问它答，是对话；你说完目标它自己跑完多步，是 Agent。
3. 2026 年 Agent 已经在编程（Codex、Claude Code）、办公（ChatGPT Work）、研究（Deep Research）三个领域规模化落地。

## 从对话到执行：本质区别

普通对话 AI 的循环是：**你提问 → 它回答 → 等你下一句**。全程你推进，它只负责生成文字。

Agent 的循环是：**你给目标 → 它自己规划步骤 → 执行一步 → 观察结果 → 修正 → 继续下一步 → 交付**。典型例子：「修复这个仓库里失败的测试」——Agent 会自己找测试文件、跑测试、读报错、改代码、再跑，直到通过。

这个循环有个正式名字：推理-行动循环（ReAct）。人类给目标，Agent 在循环里自主推进。

## Agent 的四个核心组件

**大脑（模型）。** 负责理解和决策。模型能力决定 Agent 的上限——2026 年各家都把最强推理模型优先供给 Agent 场景（如 OpenAI 把 GPT-5.6 Sol 与 Codex 深度绑定）。

**工具（Tools）。** Agent 能调用的「手脚」：读写文件、执行命令、搜索网页、调 API。工具列表决定了它能做什么类型的事。判断一个 Agent 产品的能力，先看它的工具清单。

**记忆（Memory）。** 上下文窗口内的对话是短期记忆；跨会话记住的信息（项目规范、历史偏好）是长期记忆。工程上常用一个项目说明文件（如 AGENTS.md）让 Agent 每次开工先读——这是把「记忆」外置到文件系统的做法。

**规划（Planning）。** 把大目标拆成可执行的小步骤，执行中根据反馈调整。这是 Agent 和「带工具的聊天机器人」的分水岭：会拆任务、会自我修正的才叫 Agent。

这四个组件听着挺唬人，其实就是「大脑＋手脚＋记性＋计划」。各家发布会的花活，基本是这四样换皮。

## 什么时候用对话，什么时候用 Agent

**用对话 AI 就够的场景**：问答、翻译、写作、改一段文字、解释概念——单轮交互能完成的事，开 Agent 是浪费（更慢、更贵）。

**值得用 Agent 的场景**：目标明确但步骤多的任务——「把所有报错修掉」「调研 X 并写报告」「按这份设计稿实现页面」。判断口诀：**你需要连续追问十次才能做完的事，交给 Agent 一次说完。**

丑话说在前面：Agent 不是总是更优。它消耗 token 多（多步循环每步都在烧额度）、执行有不确定性（步骤越多偏差越大）、关键决策仍需人复核。2026 年的成熟用法是「Agent 干活、人类验收」。

## FAQ

Q: Agent 和机器人是一回事吗？

A: 不是。机器人是硬件载体，Agent 是软件形态的自主执行系统。Agent 可以驱动机器人，但绝大多数 Agent（如 Codex）只存在于软件里。

Q: ChatGPT 的联网搜索算 Agent 吗？

A: 算非常初级的工具调用，但通常不算完整 Agent——它只多了一步「搜一下再答」，没有多步循环和自主规划。

Q: Agent 会失控吗？

A: 2026 年主流产品都有权限控制（如 Codex 每次执行命令前的确认机制，见[常用命令](../03-codex-tutorials/codex-cli-tutorial-2026.md)里的 `/approvals`）。给 Agent 权限的原则：测试环境放开，生产环境逐步放。

Q: 编程 Agent 和补全工具（Copilot）差在哪？

A: 补全工具在光标处猜你要打的字，你在推进；编程 Agent 接收整个任务自己推进。前者提效打字，后者提效整段工作流。
