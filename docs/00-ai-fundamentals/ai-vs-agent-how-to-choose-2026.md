# AI 与 Agent 怎么选：一张决策表分清该用哪个（2026）

> 本文是 AI 基础概念第 4 篇，是[AI Agent 是什么](what-is-ai-agent-2026.md)的实操续篇。

知道了 Agent 是什么，下一个问题是什么时候用。选错的代价真实存在：用对话 AI 干多步任务的活，你要追问十次还不一定能成；用 Agent 干一句话的活，又慢又费额度。这篇给一张能直接照着用的决策表。

赶时间的话，记住这几条就行：

1. **一句话能说清、一轮交互能完成的，用对话 AI**——更快、更便宜、结果可控。
2. **目标明确、步骤多、中间需要执行和验证的，用 Agent**——它自己跑循环，你只管验收。
3. **拿不准就先用对话 AI 试一轮**：发现自己在连续追问「然后呢」「继续」「再改改」，就是该切 Agent 的信号。

## 决策表：四个维度打分

| 维度 | 偏对话 AI | 偏 Agent |
|---|---|---|
| 任务步骤 | 一轮问答能完成 | 需要多步执行 + 中间验证 |
| 是否要动手 | 只要文字答案 | 要读写文件、跑命令、查资料 |
| 结果确定性 | 答案可直接判断对错 | 中间结果需要反馈修正 |
| token 消耗 | 少 | 多（每步循环都在消耗） |

四个维度里有三个落在右边，就用 Agent；三个在左边，用对话。模糊地带看下面的实例。

说实话这张表心里过一遍就够了。我身边到现在还有人拿 Agent 问一句话就能答的问题——高射炮打蚊子，纯浪费额度。

## 实例对照

**「把这段中文翻译成英文」**——对话 AI。单轮、纯文字、结果一眼可判。

**「帮我调研 DeepSeek 涨价对个人开发者的影响，列出去处对比」**——Agent（Deep Research 类）。需要多轮搜索、交叉核验、汇总，人肉追问效率极低。

**「解释这个报错是什么意思」**——对话 AI。贴上报错，一轮出答案。

**「修复这个仓库里所有失败的测试」**——Agent（编程类）。要跑测试、读报错、改代码、再跑验证，天然多步循环。见 [Codex 工作流实战](../03-codex-tutorials/codex-workflow-guide-2026.md)。

**「给这段邮件把语气改礼貌一点」**——对话 AI。

**「按这份设计稿实现登录页，带表单校验」**——Agent。读图、建文件、写组件、自测，多步执行。

## 容易误判的两种情况

**该用 Agent 却死磕对话**：典型症状是把大段代码反复粘贴进对话框，人工当「循环控制器」。每轮粘贴都在烧上下文，效率低于 Agent 检索式读仓库。

**该用对话却上 Agent**：问个概念、查个写法也开 Agent 任务，等两分钟拿到的答案和对话十秒出的差不多。Agent 的多步循环对单轮任务是纯开销。

还有第三种：**两者接力**。先用对话 AI 快速讨论方案、定下思路，再交给 Agent 执行——方案的人工判断 + 执行的自动化，这是 2026 年编程工作的主流姿势。

## 成本视角：为什么选型影响花费

对话按条/token 消耗，Agent 按任务消耗（一个任务 = N 轮循环 × 每轮的输入输出）。以编程为例，Codex 的用量按 token 计（2026 年 4 月起），大仓库长任务单次消耗可以是小修改的几十倍——机制见 [Codex 用量上限说明](../03-codex-tutorials/codex-usage-limits-2026.md)。所以「Agent 化」不等于无脑全自动化，高价值、重复性高的任务优先。

## FAQ

Q: 对话 AI 和 Agent 是两个产品吗？

A: 不一定。2026 年的趋势是同一产品内两种模式并存：ChatGPT 里普通对话是对话模式，Deep Research、Codex 是 Agent 模式。选模式而不是选产品。

Q: Agent 一定比对话 AI 强吗？

A: 不。同预算下 Agent 单步用的模型可能更弱（省额度），且多步累积偏差。Agent 的优势在任务完整度，不是单步智力。

Q: 新手应该从哪个开始？

A: 先把对话 AI 用熟（提问、给上下文、迭代修改），这本身就是 Agent 的输入技能——Agent 任务描述写不好，照样做不好。入门见[提示词入门](../02-chatgpt-getting-started/prompt-engineering-basics-2026.md)。

Q: 有没有两者混合的标准流程？

A: 有：对话定方案 → Agent 执行 → 对话复查结果 → 不满意再让 Agent 修。见 [Codex 工作流实战](../03-codex-tutorials/codex-workflow-guide-2026.md)的完整流程。
