# 大模型（LLM）是什么？AI 为什么会说话、写代码（2026）

> 本文是 AI 基础概念第 2 篇；机制描述采用通俗口径，忽略数学细节。

ChatGPT、DeepSeek、Claude 底层都是同一类技术：大语言模型（LLM，Large Language Model）。理解以下四个核心概念，就能看懂 AI 的绝大多数行为特征。

结论：

1. 大模型的核心机制是**预测下一个词**：给定一段文字，计算概率最高的下一个词，逐步拼接生成。
2. 它没有实时数据库与自主理解能力，知识压缩在训练参数中，因此会出现幻觉与事实错误。
3. **上下文窗口有限**导致多轮长对话后表现下滑，这也是各类长文本处理方案存在的原因。
4. 模型输出质量高度依赖给定的上下文，这是[提示词技巧](../02-chatgpt-getting-started/prompt-engineering-basics-2026.md)的底层逻辑。

## 关键词一：预测下一个词

大模型的基本任务是：给定前面的文字，计算并输出下一个概率最高的词。

例如输入「白日依山__」，模型计算出「尽」的概率极高并补全。经过海量语料训练，模型掌握了语法、事实以及逻辑推理的统计规律；写代码也是同一个逻辑：给定函数名与注释，预测最可能的实现代码。

重要推论：**模型输出的是「统计上最像答案的文字」，并不保证内容符合事实**。因此模型回答时语气通常很确定，但内容可能出错。

## 关键词二：token

模型不直接按字符处理文本，而是将其拆分为 token。英文约 1 token ≈ 0.75 个单词，中文一个汉字通常是 1-2 个 token。

token 是使用大语言模型产品的核心计量单位：

- API 按 token 计费（例如 GPT-5.6 Luna 输入 $1/百万 token，旗舰 Sol 输入 $5/输出 $30，2026 年 8 月口径）
- 用量额度按 token 计算（Codex 2026 年 4 月起改为按 token 计量，改一个小脚本和重构大仓库的消耗差几十倍）
- 上下文窗口按 token 设定上限

## 关键词三：上下文窗口

模型单次能接收的文本量存在上限，即上下文窗口。对话历史、导入的参考文档、项目代码片段，都需要占用这个窗口空间。

这对应了三个常见场景：

- **长对话后表现变差**：历史消息占满窗口容量，早期的关键提示词被丢弃或压缩。
- **超长文档无法单次处理**：文档体量超出单次窗口上限，必须分段拆解后依次处理。
- **编程工具需要检索机制**：Codex 这类工具不会将整个代码库直接传入，而是检索出相关代码片段放入窗口。

## 关键词四：幻觉

模型有时会编造看似合理但完全不符合事实的内容，比如不存在的论文引用、错误的 API、虚构的数据。其根本原因仍是词预测机制：在缺乏确切依据时，模型会优先输出符合统计语言规律的文字，而不会主动表明无法确认。

应对措施：
- 要求给出来源并提供可核验的链接；
- 对关键结论与代码参数进行人工核查；
- 补全上下文，将准确的事实数据直接写入提示词，减少自由生成的空间。

## 从大模型到产品：你在用的是什么

ChatGPT、DeepSeek、Claude 等应用等于大模型加上交互界面与工具调用能力。基础模型接入网页搜索、代码执行、文件读写等功能，便构成了不同的具体形态；接入代码库读写与终端命令执行权限后，就是 Codex 这类编程 Agent（见 [Codex 和 GPT 的区别](../03-codex-tutorials/codex-vs-gpt-difference-2026.md)）。

不同厂商的模型档位与能力差异，见[三大模型家族对比](../01-models-and-tools/gpt-vs-deepseek-vs-claude-2026.md)。

## FAQ

Q: 大模型是连着互联网搜索答案吗？

A: 默认不是。回答来自模型训练时固化在参数里的知识，受限于训练截止时间。具备联网搜索功能的产品，底层逻辑是先通过搜索引擎检索外部网页，再将检索结果拼进上下文交由模型整理生成。

Q: 为什么大模型的数学计算不靠谱？

A: 模型进行的是文本词序列预测，而不是执行确定的逻辑运算。简单的加法在训练语料中出现频率极高，正确率尚可；多位数计算容易生成错误数字。需要严谨计算时，应让模型调用代码执行器等工具。

Q: 上下文窗口越大越好吗？

A: 窗口扩大会增加可输入的材料体量，但模型的注意力更容易被分散，且推理成本和延迟显著上升。工程实践中，筛选精准相关的上下文往往比传入全部原始内容更可靠。

Q: 大模型会越来越强吗？

A: 2026 年的发展方向主要有两个：模型自身强化推理深度与长流程任务能力，工程层面则通过 Agent 架构弥补单次调用的局限（见 [AI Agent 是什么](what-is-ai-agent-2026.md)）。
