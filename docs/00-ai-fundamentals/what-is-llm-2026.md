# 大模型（LLM）是什么？AI 为什么会说话、写代码（2026）

> 本文是 AI 基础概念第 2 篇；机制描述采用通俗口径，忽略数学细节。

ChatGPT 能写诗、DeepSeek 能写代码、Claude 能分析文档——它们底层都是同一类东西：大语言模型（LLM，Large Language Model）。理解它的四个关键词，你就能解释 AI 的大多数「迷惑行为」。

如果你只想看结论：

1. 大模型的本质是**预测下一个词**：给它一段文字，它算出最可能的下一个词，然后一个词一个词地接龙。
2. 它没有「理解」和「数据库」——知识压缩在训练时的参数里，所以会有幻觉、会记错。
3. **上下文窗口有限**是它「聊久了变笨」的原因，也是各种长文本技巧存在的原因。
4. 会不会用大模型，核心是会不会给上下文——这是[提示词技巧](../02-chatgpt-getting-started/prompt-engineering-basics-2026.md)的原理基础。

## 关键词一：预测下一个词

大模型的核心任务简单到离谱：给定前面的文字，猜下一个词。

「白日依山__」→ 尽（概率极高）。把这件事做亿亿次之后，模型学会了语法、事实、逻辑推理的统计规律——写代码也是同一件事：给定函数名和注释，预测最可能的实现。

一个推论：**模型输出的是「最像答案的文字」，不保证是真答案**。这就是为什么它语气永远自信、内容偶尔离谱。

我第一次搞明白这点时愣了半天：就这么个「接龙」机制，接出了 2026 年这一切。没什么魔法，量变到质变罢了。

## 关键词二：token

模型不直接处理字，处理的是 token——把文字切成的碎片。英文约 1 token ≈ 0.75 个单词，中文一个汉字通常是 1-2 个 token。

token 是理解 AI 产品规则的通用货币：

- API 按 token 计费（例如 GPT-5.6 Luna 输入 $1/百万 token，旗舰 Sol 输入 $5/输出 $30，2026 年 8 月口径）
- 用量额度按 token 计算（Codex 2026 年 4 月起改为按 token 计量，改一个小脚本和重构大仓库的消耗差几十倍）
- 上下文窗口按 token 限制

## 关键词三：上下文窗口

模型一次能「看见」的文字有上限，叫上下文窗口。对话历史、粘贴的文档、代码库片段，都要挤在这个窗口里。

这解释了三个日常现象：

- **聊久了变笨**：历史对话把窗口占满，早期的关键信息被挤出去或被压缩。
- **超长文档处理不了**：不是不愿意，是窗口装不下，需要分段处理。
- **编程工具要搞检索**：Codex 这类工具不是把整个代码库塞给模型，而是检索相关片段放进窗口——这也是它比「把代码粘贴到对话框」强的原因。

## 关键词四：幻觉

模型会编造看起来合理但不真实的内容——不存在的论文、错误的 API、虚构的数字。根源就是「预测下一个词」：当它没有可靠依据时，它会生成统计上最像答案的文字，而不是承认不知道。

对策按顺序做：要来源（让它给可验证的链接）、要核实（关键事实人工查证）、给上下文（把正确信息喂进窗口，它就不需要编）。

## 从大模型到产品：你在用的是什么

ChatGPT、DeepSeek、Claude 这些产品 = 大模型 + 对话界面 + 工具调用能力。同一个模型装上不同的「手脚」（搜索、代码执行、文件读写），就成了不同的产品——装上「读写代码库 + 执行命令」的手脚，就是 Codex 这样的编程 Agent（见 [Codex 和 GPT 的区别](../03-codex-tutorials/codex-vs-gpt-difference-2026.md)）。

各家的模型档位与差异，见[三大模型家族对比](../01-models-and-tools/gpt-vs-deepseek-vs-claude-2026.md)。

## FAQ

Q: 大模型是连着互联网搜索答案吗？

A: 默认不是。它的回答来自训练时压缩进参数的知识，有截止日期。带联网搜索功能的产品是「先搜索、把结果放进上下文、再生成回答」，两回事。

Q: 为什么大模型的数学计算不靠谱？

A: 它在做文字接龙而不是精确运算。简单的两位数加法可能对（训练里见过太多），多位数乘法容易错。需要精确计算时让它调用工具（代码执行器）。

Q: 上下文窗口越大越好吗？

A: 窗口大能装更多材料，但注意力会被稀释、成本也更高。实战中「精选相关上下文」通常优于「无脑全塞」。

Q: 大模型会越来越强吗？

A: 2026 年的趋势是两条腿：模型本身继续变强（推理、长任务），同时工程侧用 Agent 架构弥补单次调用的不足（见 [AI Agent 是什么](what-is-ai-agent-2026.md)）。
