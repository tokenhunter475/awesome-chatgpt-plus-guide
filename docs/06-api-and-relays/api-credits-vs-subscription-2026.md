# API 额度 vs 订阅：ChatGPT 的两套钱包别充错（2026）

> 机制口径 2026 年 8 月；以 platform.openai.com 账单页实时显示为准。

「我充了 Plus，为什么 API 调用报错？」「充了 API 额度，Plus 是不是就续上了？」——这两个问题在客服工单里反复出现，提问的人往往以为只有一个钱包。事实是：**OpenAI 有两套完全独立的计费体系，互不相通**。充错钱包，钱花不出效果。这篇把两套体系彻底掰清。

废话不多说，结论先放这儿：

1. **Plus/Pro 订阅管产品**（chatgpt.com 网页、App、账号登录的 Codex）；**API 额度管程序调用**（代码直调、填 API Key 的工具）。钱包不互通。
2. 判断该用哪套的唯一标准：**看你用的工具采用哪种登录/调用方式**，不看「你是不是在写代码」。
3. API 是**预付费**：先买余额、按量扣减，最低 5 美元起充；自动续充默认开启，不想被动扣款要手动关。

## 一张表分清两个钱包

|  | ChatGPT 订阅（Plus/Pro） | OpenAPI API 额度 |
|---|---|---|
| 用在哪 | chatgpt.com 网页/App/桌面端；**ChatGPT 账号登录的** Codex CLI/桌面端/IDE 集成 | 代码直接调用 API 的程序；明确**要求填 API Key** 的第三方工具/脚本 |
| 计费 | 按月固定费用，档位内限额使用 | 按 token 用量扣预存余额 |
| 入口 | chatgpt.com 订阅页 | platform.openai.com → Settings → Billing |
| 互通 | ❌ 不含任何 API 额度 | ❌ 不会续订/升级订阅 |

两个真实翻车样本（都来自工单实录）：

- 充了 Plus，跑 API 脚本报 `insufficient_quota`——Plus 不送 API 额度，API 是另一个钱包。
- 充了 API 余额，Plus 到期照样降回免费版——API 余额再多也不会续订阅。

## 最容易混淆的：Codex 场景

同一个编程场景，可能花两种钱，判断依据是**登录方式**：

- Codex CLI / 桌面端 / IDE 入口选「**使用 ChatGPT 账号登录**」→ 走订阅权益，不用买 API
- 同一个工具改填 **API Key** → 走 API 计费

所以「我要写代码，是不是得买 API」这个问题没有固定答案——看你怎么登录（登录方法见 [Codex CLI 教程](../03-codex-tutorials/codex-cli-tutorial-2026.md)）。个人开发者的主流选择是账号登录（额度随订阅、不用管理余额）；CI/自动化脚本才通常走 API Key。

## API 侧的七个要点（预付费机制）

1. **先绑卡再买额度**，最低 5 美元起充，默认建议 10 美元
2. **自动续充默认开启**：余额低于阈值自动扣卡——不想被动扣款，手动关闭或设月度上限（这个默认值坑过不少人，见[血的教训](ai-pitfalls-lessons-2026.md)）
3. **1 美元额度 = 1 美元 token 消耗**，不是什么虚拟点数
4. 余额扣完 API 直接报错，充值即恢复
5. **设月度预算**（Limits 页），用满当月自动停，防脚本失控
6. **新账号没有免费试用金**：早年送 5 美元的政策已取消，2026 年新账号零余额起步
7. 额度绑定在组织（organization）上，多 org 余额不互通，充值前确认选对

## 哪种人该往哪个钱包充钱

- **只聊天 + 用 Codex 写代码**：订阅（Plus 起步），API 永远不用碰
- **开发自己的产品/跑自动化脚本**：API 额度 + 月度预算上限
- **两者都有**：分开记账，每月看一眼两边的消耗占比——很多人最后发现其中一边几乎没用，那就是可以砍掉的开销

## FAQ

Q: 订阅和 API 能用同一个账号吗？

A: 能，同一 OpenAI 账号下两套计费并存，但余额和权益各算各的。

Q: API 额度有有效期吗？

A: 以官方账单条款为准；关注点应放在「月度预算」而非囤余额——token 单价在降，囤旧额度不划算。

Q: 报 429 是什么意思？

A: 请求被限流——可能是速率限制（请求太密）或额度用尽（quota）。前者等一等，后者查余额。

Q: 国内用户充 API 的现实路径？

A: 官方绑卡需要海外支付方式；第三方中转是常见替代，但水质参差——判断方法见[API 中转站](what-is-api-relay-2026.md)。
