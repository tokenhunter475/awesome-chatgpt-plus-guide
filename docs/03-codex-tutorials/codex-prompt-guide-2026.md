# Codex 提示词实战：任务描述、上下文给法、分步提交技巧（2026）

> 实战口径来自社区验证过的用法；通用提问基础见[提示词入门](../02-chatgpt-getting-started/prompt-engineering-basics-2026.md)，本文只讲编程场景。

「开了 Plus，甩一句『帮我做个功能』，效果一般」——这是 Codex 最常见的翻车姿势。同样的模型，任务描述质量不同，成功率差距可以到数倍。这篇讲四个实战技巧，全部带对照示例。

挑重点说：

1. **任务拆小**：一次一个职责单一的任务，大需求拆 4-5 步提交。
2. **上下文五要素**：目标、文件、约定、参考、验证——每个任务描述过一遍这个清单。
3. **项目约定写进 AGENTS.md**，一次配置全局生效。
4. 最强的省返工技巧：**让它先跑测试、先写测试**。

## 技巧一：任务拆小，不要一次甩一整个需求

云端/本地任务越大，出错概率越高，调试成本也越高。

> ❌ 「帮我做一个完整的用户管理系统，包含注册、登录、权限管理和数据导出」
> ✅ 「在 src/api/auth/ 目录下实现用户注册接口，使用 bcrypt 哈希密码，Zod 做参数校验，返回 JWT token」

后者一次就能跑对。前者的正确打开方式是拆四步：注册 → 登录 → 权限 → 导出，每步验证后再进行下一步。宁可多提交几次，不要赌一次大的。

## 技巧二：上下文五要素（抄走即用的结构）

Codex 能读你的仓库，但它**不知道你的项目约定和意图**。每个任务过一遍这五项：

```
目标：[要做什么]
文件：[改哪些文件/目录]
约定：[框架、版本、代码规范]
参考：[现有的类似实现在哪里]
验证：[怎么判断做对了]
```

实例：

> 目标：给 /api/orders 接口加分页
> 文件：src/app/api/orders/route.ts
> 约定：项目用 Next.js 15 App Router + Supabase
> 参考：/api/articles/route.ts 里已实现分页，按那个模式来
> 验证：GET /api/orders?page=2&limit=10 返回正确的分页数据

这五要素不是什么秘籍，就是把「你跟新同事交代需求」的话原样写下来。平时怎么跟人交代活，就怎么跟 Codex 交代，够了。

其中**「参考」最值钱**——给它一个现成的正确样板，比十句形容词都管用；**「验证」次之**——有了可执行的验收标准，它会自己跑检查再交付（配合技巧四）。

## 技巧三：项目约定写进 AGENTS.md，不要每次重复

在仓库根目录放一个 `AGENTS.md`，写清：技术栈和版本、目录结构、命名约定、常用命令（测试/构建/部署）、代码风格偏好。Codex 每次执行任务会自动读取——一次写好，之后所有任务受益。

这是「把记忆外置」的标准做法（原理见 [Codex 记忆与配置](codex-memory-and-config-2026.md)）。反模式是在每次任务描述里重复贴规范——既冗长又容易漏。

## 技巧四：先测试，再改代码

两个层级：

**基础版**：任务描述里加一句「先跑现有测试确保通过，改完之后再跑一遍」——大幅降低引入回归 bug。

**进阶版（TDD 模式）**：让它先写测试再实现：

> 1. 先在 tests/api/orders.test.ts 写分页功能的测试用例
> 2. 然后修改 src/app/api/orders/route.ts 实现分页
> 3. 确保所有测试通过

测试先行给了它明确的「完成」信号，也给了你明确的验收物——这种模式和 Codex 的异步执行特别契合（见[云端任务](codex-cloud-tasks-2026.md)）。

## 附加技巧：图片输入

Codex 支持图片：直接贴设计稿或 UI 截图，让它生成前端代码。实测参考：Figma 截图转 React 组件还原度约 70-80%，手绘草图能出可用原型。搭配提示词：

> 根据这张截图实现一个 React 组件，使用 Tailwind CSS，响应式设计，配色和布局尽量还原。

报错也可以截图——它读得懂截图里的报错文字（多模态）。

## 常见翻车对照

| 翻车姿势 | 修正 |
|---|---|
| 一次甩整个大需求 | 拆成单一职责的小任务链 |
| 「帮我优化一下这段代码」 | 写明维度：性能/可读性/安全，和验收标准 |
| 不给参考实现 | 指出仓库里最像的现成代码 |
| 验收靠肉眼 | 给可执行验证（测试、命令、URL） |
| 每次重复贴项目规范 | 移进 AGENTS.md |

## FAQ

Q: 任务描述写中文还是英文？

A: 都支持。中文描述 + 代码标识符英文是最常见组合；关键是结构和上下文，不是语言。

Q: 小任务也要五要素吗？

A: 不用凑满——「改个文案」这种只需要目标+文件。清单是给「卡壳时排查用的」：结果不满意，回头检查八成是漏了某一项。

Q: 怎么让它别改不该改的文件？

A: 「文件」要素里明确范围，并声明「不要改动其他文件」；权限层面用确认模式（`/approvals`，见 [CLI 教程](codex-cli-tutorial-2026.md)）兜底。

Q: 这些技巧适用于其他编程 AI 吗？

A: 适用。任务拆解、上下文、验收标准是所有编程 Agent 的通用语言（对照见[AI 与 Agent 怎么选](../00-ai-fundamentals/ai-vs-agent-how-to-choose-2026.md)）。
