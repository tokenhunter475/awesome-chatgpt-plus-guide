# Codex 网页版与云端任务：chatgpt.com/codex 用法与本地/云端怎么选（2026）

> 功能入口随版本更新调整，以产品内实际显示为准；本文 2026 年 8 月更新。

Codex 不只是终端工具——网页版（chatgpt.com/codex）能提交云端任务：你说完需求就关电脑，它在 OpenAI 的沙盒里自己跑，跑完通知你。很多人不知道这个形态，或不知道什么时候该用它。这篇讲清楚。

先说结论：

1. **一轮对话能出结果的小任务用本地**（CLI/IDE），快、可随时打断追问。
2. **多文件、多步骤、预计要跑很久的任务用云端**：提交后不用盯着，还能并行多个。
3. 本地和云端**共享同一份额度**——省额度的意识要带着，不是「放云端就免费」。

## 云端任务是什么

本地会话（CLI / IDE 插件）是实时交互：你问，它答，你的机器是执行环境。

云端任务是你提交一个目标（如「给这个仓库的订单模块加统一错误处理，跑通所有测试」），Codex 在 OpenAI 的沙盒里自主执行：拉代码、分析、修改、跑测试，完成后给你结果和改动说明。单个任务通常 1-30 分钟（任务越大越久），期间你可以关页面、干别的。

关键差异一句话：**本地 = 你陪它干；云端 = 它自己干，你验收。**（两种模式的原理对照见 [AI 与 Agent 怎么选](../00-ai-fundamentals/ai-vs-agent-how-to-choose-2026.md)。）

## 怎么用网页版

1. 打开 chatgpt.com/codex，用 ChatGPT 账号登录（免费账号可用，模型为 Terra 轻量档）。
2. 新建任务：写清目标 + 约束（提示词写法见 [Codex 提示词实战](codex-prompt-guide-2026.md)）。
3. 提交后等通知，回来查看：改动 diff、执行日志、结论。
4. 满意就采纳改动；不满意给反馈让它改。

**并行**：可以同时提交多个云端任务（如同时修三个独立 bug、一个写测试一个重构），到点一起收。重度用户这是最大的效率杠杆——注意额度消耗也是并行的。

## 本地 vs 云端：选择策略

| 维度 | 本地（CLI/IDE） | 云端（网页版） |
|---|---|---|
| 交互 | 实时对话，可打断追问 | 提交后异步，等结果 |
| 时长 | 跟随会话 | 单任务 1-30 分钟 |
| 适合 | 快速迭代、探索式修改 | 大重构、批量任务、跑测试 |
| 环境访问 | 你的本机（受权限控制） | OpenAI 沙盒（隔离环境） |
| 消耗 | 实时计 | 按任务计，大任务消耗高 |

实用原则：**需求能在对话里说清并马上要结果 → 本地；需求要「跑一阵子」且你不想盯 → 云端。** 拿不准先本地试两轮，发现「我在等它」的时间变多，就是转云端的信号。

## 额度：云端任务的隐形账单

云端任务共享账号额度（5 小时窗口 + 周上限，机制见[用量上限说明](codex-usage-limits-2026.md)），而大任务的 token 消耗远高于小修改——每一轮都要重发上下文给模型。三点控制手段：

1. **任务描述里给足上下文**（参考文件、验收标准），减少它来回试错——这是最大的省额度杠杆。
2. **大任务拆成边界清晰的小任务**，一次说不清的「顺便把……也改了」式任务最容易烧钱。
3. **跑批式任务避开额度紧张期**，提交前用 `/status`（本地）或用量页看余量。

另外记住：ChatGPT Work 的智能体与 Codex **共享同一个用量池**（2026 年 7 月起），两边同时重度使用会互相挤占额度。

## FAQ

Q: 云端任务失败会浪费额度吗？

A: 执行中消耗的 token 已发生。减少失败的核心还是任务描述质量：给参考实现、给验收标准（「跑通所有测试」就是好验收）。

Q: 云端任务能访问我的数据库/内网吗？

A: 不能——它在隔离沙盒里执行，访问范围受限于任务机制设计。涉及内部环境的任务走本地（权限可控）。

Q: 手机能用吗？

A: 能。网页版和 ChatGPT App 里的 Codex 入口支持发起任务，配合手机正好利用「等云端任务」的碎片时间。

Q: 云端任务和 Deep Research 什么区别？

A: 云端任务改代码（在仓库沙盒里执行），Deep Research 做调研（多轮搜索产出报告）。一个动手，一个动嘴。
