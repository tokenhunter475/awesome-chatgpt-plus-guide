# Codex 工作流实战：一个需求从接到到上线的完整流程（2026）

> 实战口径来自验证过的用法；命令细节见 [CLI 教程](codex-cli-tutorial-2026.md)，本文专注流程本身。

会用命令和会用 Codex 干活是两回事。这篇用一个真实需求走完整流程：接到「给订单模块加导出功能」——从拆解到验收，每步给可照抄的指令。这是把前面所有单点技巧串起来的总装篇。

懒得看全文？重点就这几条：

1. 标准流程五步：**拆解 → 测试先行 → 实现 → 审查 → 人工验收**。
2. 人的角色是**定义问题和验收结果**，中间执行交给 Codex——但最后一步永远是人。
3. 最大的流程错误只有一个：**跳过测试直接让它写实现**。

## 第 0 步：开工前的两个准备

**确认 AGENTS.md 存在且最新**（项目约定、常用命令）。没有的话先花 10 分钟写——后面每一步都受益（写法见[记忆与配置](codex-memory-and-config-2026.md)）。

**确认权限模式**：探索性任务用确认模式（每步过目），熟悉后的常规任务用自动模式提效（`/approvals` 切换）。

## 第 1 步：拆解需求（人做）

「加导出功能」直接甩给 Codex 是翻车的开始。拆成职责单一的步骤：

1. 数据层：订单查询支持时间范围筛选
2. 服务层：CSV 生成（含表头、分批读取，避免大订单内存溢出）
3. 接口层：导出端点 + 权限校验
4. 测试：三个层次的用例

拆解的标准：**每步能单独验证**。参考[提示词实战](codex-prompt-guide-2026.md)的五要素清单。

## 第 2 步：测试先行（让 Codex 写）

> 指令示例：「在 tests/api/orders-export.test.ts 写导出功能的测试用例：时间范围筛选、CSV 表头格式、空结果集。参考 tests/api/orders.test.ts 的写法。先不要写实现。」

测试是验收标准的代码化——有了它，第 3 步的实现有了明确的「完成」信号，你也可以先审测试（便宜）再实现（贵）。

## 第 3 步：实现（Codex 干，分步提交）

> 指令示例：「实现 orders 导出：按刚才的测试用例，改 src/api/orders/ 下相关文件。约束：用现有的分页工具函数，单次查询上限 1000 条，分批聚合。改完跑全部测试。」

要点：**参考**（已有的分页写法）、**约束**（防它自由发挥出过度设计）、**验证**（跑测试）。每完成一个子任务，快速过目 diff 再继续下一个——发现跑偏立即纠，别攒到最后。

**并行提效**（适合独立子任务）：相互不依赖的任务（如「给三个独立模块各写单测」）可同时提交多个云端任务，到点一起收（机制见[云端任务](codex-cloud-tasks-2026.md)）。有依赖关系的任务不要并行。

## 第 4 步：代码审查（Codex 的强项）

> 指令示例（或直接 `/review`）：「Review 本次导出功能的全部改动，重点：安全漏洞（权限绕过、注入）、边界情况（超大订单、并发导出）、性能问题。给出具体改进建议。」

Codex 审查以严谨著称（见[编程工具对比](../01-models-and-tools/ai-coding-tools-comparison-2026.md)）。完整方法见[代码审查专篇](codex-code-review-2026.md)。

## 第 5 步：人工验收（不可替代）

上线前人必须过三样：

1. **diff 通读**：改动是否越界（改了不该改的文件）
2. **功能实测**：真实环境跑一遍核心路径
3. **测试全绿确认**：不是「它说过了」，是自己跑一遍

原则：**Codex 负责正确性努力，你负责正确性责任。** AI 生成代码的 bug 特点是「看起来对」——测试和实测是唯一兜底。

## 常见流程错误

| 错误 | 后果 | 修正 |
|---|---|---|
| 跳过测试直接实现 | 验收靠肉眼，回归靠祈祷 | 永远测试先行 |
| 一次提交整个大需求 | 错误连坐，返工成本高 | 拆到能单独验证 |
| 改完不看 diff | 越界改动溜进主线 | 每步过目 |
| 把验收外包给 AI | 责任错位 | 人做最后一步 |
| 无 AGENTS.md 硬开工 | 每个任务重复交代规范 | 开工前先写 |

## FAQ

Q: 这个流程适合小改动吗？

A: 缩水版适合：小改动可合并为「测试+实现」一步提交，但审查和人工验收不省。流程的重量与改动的大小成正比，最后两步是常量。

Q: TDD 会不会反而更慢？

A: 首次多花写测试的时间，省下的是返工和 review 时间。对 Agent 协作尤其划算——测试是唯一无歧义的验收语言。

Q: 多人团队怎么共用这套流程？

A: 把流程本身写进 AGENTS.md 或封装成技能（见[Skills 用法](codex-skills-guide-2026.md)），团队所有人的 Codex 按同一套打法执行。

Q: 每一步都要新开会话吗？

A: 不用。同一任务链在一个会话里连续推进（上下文延续有助一致性）；跨天用 `/resume` 恢复（见[记忆与配置](codex-memory-and-config-2026.md)）；不同主题换新会话。
