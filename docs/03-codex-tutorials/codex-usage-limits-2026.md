# Codex 用量上限说明 2026：5 小时窗口、周上限与 usage limit 解决方法

> 限额规则随 OpenAI 政策调整频繁，以 `/status` 输出和官方文档实时口径为准；本文 2026 年 8 月更新。

正写着代码，Codex 弹出 "You've hit your usage limit"，任务卡在一半——这是 2026 年 Codex 用户最高频的报错。处理它只需要两步：先判断撞的是哪把锁，再选对应的恢复路径。

简单来说：

1. **先跑 `/status`**（CLI）或看 ChatGPT 设置里的用量页，判断是 5 小时窗口还是周上限。
2. **撞 5 小时窗口**：等一等就好，滚动恢复，通常几小时内回来。
3. **撞周上限**：在「等下周」「加购 Credits」「升级套餐」「改用 API」里按用量选一条，见下文第五节。

## 机制：每个套餐同时挂着两把锁

Codex 的用量不是单一池子，而是两层限制同时生效：

| 限额类型 | 机制 | 撞上后的表现 |
|---|---|---|
| 5 小时滚动窗口 | 短时高强度使用触发，随时间滚动恢复 | 报错，但通常几小时内自动恢复 |
| 每周上限 | 一周总量封顶 | 5 小时窗口恢复了也照样用不了 |

两把锁**互相独立**：周上限耗尽时，即使 5 小时窗口还有余量也用不了；反过来，窗口重置只恢复窗口额度，不给周上限「回血」。

第一次搞懂这「两把锁」的时候我是有点无语的——对用户确实不友好。但吐槽归吐槽，规则就是规则，摸清了才不吃亏。

档位决定锁的松紧：免费档和 Go 档额度有限且不能加购，Plus 日常开发够用，Pro 给到 Plus 的约 5 倍（$100 档）或 20 倍（$200 档）。各档位完整对比见 [Codex 和 GPT 的区别](codex-vs-gpt-difference-2026.md)。

## 为什么额度掉得比你想象的快

「我才用了一小会儿就到上限了」——这类反馈在 OpenAI 官方论坛很常见。四个主要原因：

**1. 计量单位是 token，不是消息条数。** 2026 年 4 月起，Codex 用量改为按 token 消耗计算。同样是「发一条消息」，改一个小脚本和重构一个大仓库，消耗可能差几十倍。在大型代码库上跑长任务，额度掉得快是正常现象。

**2. 本地和云端共用一个池子。** CLI 里的会话和云端执行的任务（包括从手机发起的 Codex 任务）共享同一份额度。只记得终端里用了多少、忘了云端还挂着任务，是常见误判。

**3. Codex 额度和其他 Agent 功能绑定。** Codex 的用量计入账号的 agentic 用量上限，和 ChatGPT 的其他 Agent 类功能共用一个池。同时用多个 Agent 功能时，Codex 可用额度会被一起消耗。

**4. 偶尔是官方的事故。** 2026 年 6 月 28 日起，OpenAI 状态页记录过一次「Codex 用量消耗异常偏快」事故，持续约 3 天；更早的 4 月，OpenAI 因限额争议给全部付费用户清空过一次限额作为补偿。撞限额时先看一眼 [status.openai.com](https://status.openai.com/) 有没有进行中的事故，别急着怪自己。

## 恢复时间怎么算

- **5 小时窗口**：滚动恢复，不是整点重置。10:00 的高强度使用，大约 15:00 前后释放对应额度。`/status` 会给出具体重置时间点。
- **周上限**：按周重置，同样以 `/status` 或用量页显示为准。
- **任务中途撞限**：Codex 通常会把当前这个任务做完（受合理使用限制约束）再要求处理，不用担心改到一半的代码被扔下。

一个已知 bug：`/status` 显示额度健康、实际却持续报限额（社区称 phantom limit，最早在 v0.124.0 版本报告）。遇到就把 CLI 升级到最新版、退出重新登录；仍不行带着 `/status` 截图去 GitHub 仓库提 issue。

## 五条解决路径：从免费到付费，按顺序过

**路径 1：等待重置（免费）。** 撞的是 5 小时窗口、不赶时间，这是最优解。把大任务拆小、避开连续长会话，能明显降低撞墙频率。

**路径 2：用攒下的存量重置（免费）。** Codex 支持把符合条件的限额重置「存起来」以后用（savable resets），覆盖 Go/Plus/Pro 等含 Codex 的订阅；部分官方活动也会赠送。检查用量页有没有可用存量。

**路径 3：加购 Credits（小额付费）。** 部分 Plus 和 Pro 用户可直接购买 Credits：订阅内额度先扣，扣完自动用 Credits。适合偶尔超量的用户；不是所有账号都有入口，以用量页显示为准。

**路径 4：升级套餐（订阅付费）。** 每周都撞周上限，说明档位已不匹配用量，逐次买 Credits 反而更贵。从 Plus 往上有 Pro 的 $100（5X）和 $200（20X）档，额度差距显著。

**路径 5：改用 API 按量付费。** API key 走 Codex 没有 5 小时窗口和周上限，纯按 token 计费。适合用量极不规律或接 CI/自动化流程的团队；重度使用下总费用可能远超订阅，自己算账。

## 什么情况不需要处理

- 一周撞一两次 5 小时窗口：正常现象，等恢复即可，不值得为此花钱。
- 学习和轻量使用：免费/Go 档撞限是设计内的，等重置比加购划算。
- 事故期间：官方事故导致的消耗异常，等公告处理，别基于异常数据做升级决策。

## FAQ

Q: /status 显示还有额度，为什么还是报 usage limit？

A: 已知的 phantom limit bug。升级 Codex CLI 到最新版、退出重新登录；仍不行带 `/status` 截图去官方 GitHub 仓库反馈。

Q: 5 小时窗口是整点重置吗？

A: 不是，滚动恢复。从每段高强度使用开始算约 5 小时后释放，具体时间点看 `/status`。

Q: 周上限重置会同时恢复 5 小时窗口吗？

A: 两者独立。周上限按周重置，5 小时窗口滚动恢复，互不影响。

Q: Credits 所有账号都能买吗？

A: 不是。部分 Plus/Pro 账号有入口，以用量页实际显示为准。

Q: API 按量付费更便宜吗？

A: 不一定。API 没有窗口和周上限、按 token 实算，轻中度使用可能更省，重度使用通常比订阅贵。建议先估算自己的日均 token 量再决定。

Q: 额度和套餐档位是什么关系？

A: 档位决定两把锁的容量：免费/Go 有限且不可加购，Plus 够日常开发，Pro 是 5-20 倍。详见 [Codex 和 GPT 的区别](codex-vs-gpt-difference-2026.md)。
