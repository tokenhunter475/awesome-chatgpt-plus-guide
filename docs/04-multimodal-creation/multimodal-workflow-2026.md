# 多模态进工作流：截图问答、设计稿转代码、配图一条龙（2026）

> 实战口径 2026 年 8 月；功能入口以各产品实际界面为准。

单聊「图片模型」或「视频模型」意义有限，把它们**当接口嵌进已有工作流**才有产出。这里梳理四个已经跑通的日常场景与完整链路：

1. 价值排序：**截图问答 > 配图生产 > 拍照识别 > 设计稿转代码**（越往后越偏专业场景，但天花板更高）。
2. **图是输入也是输出**：把「看图」和「出图」接入同一项工作，才算完整工作流。
3. Codex 能直接读设计稿截图生成代码，还原度七成起。

## 场景一：截图问答

遇到排查或理解问题，优先截图：

- 软件报错弹窗 → 截图发给 ChatGPT：「这是什么错，怎么解决」
- 复杂的英文界面 → 截图：「把这段翻译并解释这个设置的作用」
- 复杂图表 → 截图：「图里的关键结论是什么」

**截图比文字描述更精确**。打字形容报错容易遗漏信息，截图不会。当前视觉模型的 OCR 和图表理解已经稳定，是多模态中投入产出比最高的使用习惯。

## 场景二：拍照识别

直接拍照输入物理世界的信息：设备铭牌（「这个型号的默认密码怎么重置」）、植物病害、商品标签比价或外语菜单。注意隐私边界，不要上传包含敏感信息或他人隐私的画面（见[数据安全](../00-ai-fundamentals/ai-data-security-2026.md)）。

## 场景三：设计稿转代码

Codex 支持图片输入，可以直接传设计稿：

> 根据这张截图实现一个 React 组件，使用 Tailwind CSS，响应式设计，配色和布局尽量还原。

实测参考（社区口径）：Figma 截图生成 React 组件，还原度约 70-80%；手绘草图可以转出可用原型。流程如下：

1. 截取设计稿（或拍摄手绘草图）
2. 连同技术栈约定发给 Codex（约定写入 AGENTS.md 可以省去重复说明，见[记忆与配置](../03-codex-tutorials/codex-memory-and-config-2026.md)）
3. 生成初版后对照截图提修改（例如「按钮间距收紧、标题加粗」）
4. 补齐响应式和边界情况

这套流程能省去大部分从设计到前端界面的手动还原工作。提示词细节见 [Codex 提示词实战](../03-codex-tutorials/codex-prompt-guide-2026.md)。

## 场景四：文章配图流程

以公众号文章配图为例，将各环节串联：

1. **写作**：文本模型起草（[提示词](../02-chatgpt-getting-started/prompt-engineering-basics-2026.md)给足上下文）
2. **配图**：[AI 生图](image-models-guide-2026.md)生成封面和插图，提示词中固定风格描述、仅修改主体，保持视觉一致
3. **图内文字**：短词组直接在生图时生成；长文案建议在图片留白处由排版工具后期添加
4. **动态头图**：挑选一张头图，用[图生视频](video-models-guide-2026.md)生成 5 秒动态素材
5. **音频朗读**：文案直接输入 TTS 生成配音（见[音频入门](audio-and-voice-ai-guide-2026.md)）

整套流水线的每个环节都可以独立使用，按需组合即可。

## 多模态的局限

- **高精度图片**（工程图、数据图表定稿）：AI 生图不可靠，需使用专业制图工具；数据可视化建议直接通过代码绘制（Codex 生成图表代码更精准）。
- **长视频**：视频模型目前仍以短素材生成为主（见[视频入门](video-models-guide-2026.md)）。
- **避免过度使用**：文字能清晰说明的内容，强行配图反而稀释信息密度。

## FAQ

Q: 截图里有机密信息怎么办？

A: 先脱敏（对关键数据打码）再上传。所有上传内容应按「可能被服务方读取」的标准处理（见[数据安全](../00-ai-fundamentals/ai-data-security-2026.md)）。

Q: 免费账号能用多模态吗？

A: 图片理解（读图）在多数产品中免费可用；生图和生视频通常按订阅档位分配额度。

Q: 设计稿转代码还原不到 100%，价值在哪？

A: 70-80% 的还原度意味着结构、布局和配色可以一次成型，后续只需微调。相比从零编写，节省的是基础排版代码的手写时间。

Q: 这些场景应该先用哪个？

A: 截图问答。操作门槛最低，见效最快。
